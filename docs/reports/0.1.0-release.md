closes the items that audit deferred. The verdict is at the end.

### Maintainability

- Found: the binary identity check lived only in `check_generated.py` while
  four other paths ran the CLI; the asset and version logic would otherwise
  be repeated per script; the CI corpus step built its own environment.
- Changed: `scripts/tscli.py` is the single CLI path (identity, private
  parser and configuration directories, subprocess, timeouts, `parse`,
  `cst`, `has_error`), `check_generated.py` keeps only pin, lockfile,
  scanner and drift duties, and a structural test fails if a script builds
  the binary path itself or a CI step runs a command outside its allowlist
  (`npm ci`, check scripts, git; Session 05-1, Reviewer C C-03). Terminated processes are only the
  scripts' own children.
- Not changed: no grammar refactor. The textual duplicates in `grammar.js`
  are required (`_try_body` keeps `catch` an identifier outside TRY bodies,
  grammar-design §4; statement chains exclude optional chaining, §6) or
  would change `parser.c` for no concrete problem. Remaining debt: Markdown
  table parsing is repeated in `check_registry.py` and `check_schema.py`;
  the list of generated files appears in `check_v0.py` and
  `check_generated.py`; the `package.json` scripts run the npm binary
  directly (documented as conveniences, not evidence).

## Performance

[0.1.0-performance.md](0.1.0-performance.md): valid input from 852 B to
5 MB parses at 3–5 MiB/s (5 MB in 1.23 s, peak working set 156 MiB); deep
nesting and every valid scaling family grow linearly; incremental reparses
of nine kinds of edit take 1.3–1.8 % of a fresh parse and equal it; the
highlight query is linear in its captures. Recovery is linear on every
malformed family measured except one: repeated malformed prefix `+`/`-`
operators inside one expression take quadratic time (KL-002; 8 KB: 5.6 s
native, 14 s through the CLI), which the final review found (B-01). No
optimisation was made.

## Comparative conformance

[0.1.0-comparative-conformance.md](0.1.0-comparative-conformance.md):
against the legacy grammar (`253fdfaa`, `0c534d56`) on one runtime,
0.1.0 parses all 97 documented requirements and rejects the input of all 6
invalid ones; the legacy grammar misses or misparses 54 documented
requirements, accepts the invalid input of 3, and reproduces known
regressions KR-001–KR-006. No documented or invalid requirement is handled
correctly by the legacy grammar and incorrectly by 0.1.0; in one
out-of-scope row (BS-COND-014) the legacy grammar rejects designator probes
that 0.1.0 accepts as a disclosed non-goal. The legacy grammar recovers
faster from the KL-002 malformed family, which it cannot build because it
has no prefix `+`/`-`.

## Known limitations

- KL-002 ([validation.md](../validation/validation.md), details in
  [0.1.0-performance.md](0.1.0-performance.md#known-limitation-kl-002)):
  error recovery takes time quadratic in the number of consecutive
  malformed prefix-operator pairs (`+` or `-` followed by a token that
  cannot start an operand) inside one expression; through the CLI such a run
  exceeds 10 s from about 7 KB. Tree-sitter runtimes 0.25.1–0.27.0 behave
  alike; valid input and scattered errors are not affected. Consumers that
  parse untrusted text can bound parse time with the runtime's progress
  callback.
- No Level 2 (Roku device or compiler) evidence exists; V8 was not run.
  "Verified on Roku" is not claimed.
- Provisional (25), a disclosed grammar choice that Level 2 evidence may
  change: BS-LEX-003, 006, 008, 014, 024, 025, 028, 033, 035; BS-LIT-006,
  010, 017; BS-EXP-021, 027; BS-STMT-008, 009, 020, 022, 026, 032, 033;
  BS-FUNC-003; BS-ERR-005; BS-COND-008, 012.
- Tolerated (10), non-normative and resting on Level 4 evidence: BS-LEX-011;
  BS-STMT-004, 011, 035, 039, 040; BS-FUNC-011; BS-ARRAY-003; BS-AA-004;
  BS-COND-015.
- Unresolved (25), not claimed either way: BS-LEX-007, 016, 020, 034;
  BS-LIT-013, 018; BS-TYPE-002; BS-EXP-022–025; BS-STMT-006, 014, 021, 028,
  034; BS-FUNC-004, 007, 012; BS-ARRAY-006, 009; BS-AA-006; BS-ERR-006;
  BS-COND-009, 010.
- Not rejected although the compiler would reject them (grammar-contract
  non-goals): reserved words used as names where they are not grammar
  keywords, literal words included (`step = 1`, `catch true`,
  `#const x = invalid`; BS-LEX-023), designators on function and constant
  names (BS-LEX-019, BS-COND-014), semantic rules (out-of-scope rows).
- Disclosed behaviour on invalid input: a word that begins with a contextual
  keyword or directive word may be split instead of rejected (`a modx`,
  `#iffy`); a label after code on the same line (`x = 1 : here:`) is
  accepted (BS-LEX-028, not contractual); inside a literal-false region a
  line whose first word is exactly `#if`, `#else` or `#end` is a directive
  (grammar-design §11); recovery
  trees are not contractual, and a missing block terminator can leave later
  declarations inside one `ERROR`.
- No language bindings, no WASM artifact, no package; consumers use `src/`.
- `go-treesitter`: V9 did not pass (recovery-tree differences in the Go
  runtime, `go-treesitter` KR-0005, on inputs with syntax errors). This
  repository makes no `go-treesitter` compatibility claim; the integration
  and its correction are separate work in that repository, on the released
  identity.
- Performance is measured on one Windows machine; the slowest measured
  family is KL-002; apart from it, malformed input with bare CR line endings
  (0.2 MiB/s, linear).
