remediation continuation Session 05-1, 2026-09-24). It builds on the release

hold ([Status: hold](#status-hold)). Statements below that these findings

## Session 05-1 changes

The Session 05 final review found B-01 (quadratic error recovery on
repeated malformed prefix `+`/`-` operators, `PERFORMANCE_MATERIAL`), and
Session 05 stopped at `7d1c8c0` (`HOLD_FOR_RELEASE_REMEDIATION`). Session
05-1 isolated the cause: the Tree-sitter runtime's error recovery (runtimes
0.25.1, 0.26.13 and 0.27.0 alike) together with the documented operator
structure and the nested encoding of prefix operators; generators 0.26.13 and
0.27.0 emit identical files, and no grammar change was found that keeps both the language
and the nested `unary_expression` tree. The owner accepted B-01 as KL-002.
Its independent re-audit of `e1a5da2` found a second mechanism, the
runtime's end-of-input acceptance: unclosed calls and indexes took quadratic
time and memory (1.24 GiB at 6 KB) because the postfix operand was inlined,
and runs of malformed `^` did so because the left operand of `^` was a plain
`expression`.
The owner approved the grammar fix for the first and first accepted the
second as KL-003, with an exception to the bounded-memory condition. The
final re-audit of `d55e3a6` showed a tree-preserving change that bounds the
`^` memory (the owner approved it; KL-003 is retired, the exception
withdrawn) and found further quadratic-time families: nested single-line IFs
with a condition broken across a line, directives inside an expression, and
the known families continued across lines. None needs more than small memory,
and the progress callback stops them all. The owner chose to disclose them as
one class, KL-002, with the measured families listed and the list declared
not exhaustive ([0.1.0-performance.md](0.1.0-performance.md#known-limitation-kl-002)).
The delta re-audit of `038fa28` found runs of malformed PRINT items whose
recovery needed quadratic memory that the progress callback could not
interrupt (1.44 GiB at 32 KB through the CLI; present since the Session 05 parser). The owner
approved a tree-preserving change, on the condition that a family sweep and
the full gates pass. It bounds that memory, and PRINT continued by malformed
lines now takes quadratic time instead, as a member of KL-002. Every change
keeps `src/node-types.json`.

### Maintainability

- Found: the binary identity check lived only in `check_generated.py` while
  four other paths ran the CLI; the asset and version logic would otherwise
  be repeated per script; the CI corpus step built its own environment.
- Changed: `scripts/tscli.py` is the single CLI path (identity, private
  parser and configuration directories, subprocess, timeouts, `parse`,
  `cst`, `has_error`), `check_generated.py` keeps only pin, lockfile,
  scanner and drift duties, and a structural test fails if a script names a
  CLI launcher or starts a program other than git, a CI step runs a command
  outside its allowlist (`npm ci`, check scripts, git, without shell
  metacharacters) or `package.json` gains an npm lifecycle script (Session
  05-1). It guards against accidental regressions in the forms it
  recognises; it is not a sandbox. Terminated processes are only the
  scripts' own children.
- Not changed: no grammar refactor. The textual duplicates in `grammar.js`
  are required (`_try_body` keeps `catch` an identifier outside TRY bodies,
  grammar-design §4; statement chains exclude optional chaining, §6) or
  would change `parser.c` for no concrete problem. Remaining debt: Markdown
  table parsing is repeated in `check_registry.py` and `check_schema.py`;
  the list of generated files appears in `check_v0.py` and
  `check_generated.py`; the `package.json` scripts run the npm binary
  directly (documented as conveniences, not evidence).

## Performance

[0.1.0-performance.md](0.1.0-performance.md): valid input from 852 B to
5 MB parses at 3–5 MiB/s (Session 05 parser; the release parser parses the
5 MB input in 0.69 s, peak working set 161 MiB); deep nesting and every
valid scaling family grow linearly; incremental reparses of nine kinds of edit
take 1.3–1.7 % of a fresh parse on the release parser and equal it; the
highlight query is linear in its captures, except within one PRINT statement
with many items on the release parser (open, [Status: hold](#status-hold)).
Correction (2026-09-25): that holds for the inputs measured there only. The
query was also quadratic on valid chains of member, attribute and method
accesses and on flat `ERROR` nodes (S07-M03); Session 05-3 made member and
attribute chains linear, and the rest is open
([0.1.0-structural-recovery-safety.md](0.1.0-structural-recovery-safety.md)).
Recovery is linear on every
malformed family measured except the KL-002 class, which takes quadratic time
with small memory (through the CLI: PRINT continued by malformed lines 6 KB
12.9 s, prefix operators 8 KB 6.4 s, `^` 12 KB 6.8 s, nested single-line IFs
28 KB 9.0 s; at most 24 MiB). Unclosed calls and indexes, and the memory of the
`^` and PRINT families, grew quadratically until the Session 05-1 grammar
fixes (calls, 6 KB native: 2.7 s and 1.24 GiB before, 6 ms and 7.5 MiB after;
`^`, 24 KB native: 1.11 GiB before, 18 MiB after; PRINT items, 32 KB native:
1.43 GiB before, 31 MiB after). No other optimisation was made. The round-5
re-audit found further families with quadratic memory and a stack overflow
on long malformed PRINT runs (open, [Status: hold](#status-hold)).

## Comparative conformance

[0.1.0-comparative-conformance.md](0.1.0-comparative-conformance.md):
against the legacy grammar (`253fdfaa`, `0c534d56`) on one runtime,
0.1.0 parses all 97 documented requirements and rejects the input of all 6
invalid ones; the legacy grammar misses or misparses 54 documented
requirements, accepts the invalid input of 3, and reproduces known
regressions KR-001–KR-006. No documented or invalid requirement is handled
correctly by the legacy grammar and incorrectly by 0.1.0; in two
out-of-scope rows (BS-COND-014 and BS-ERR-007) the legacy grammar rejects
inputs that 0.1.0 accepts as a disclosed non-goal. The legacy grammar
recovers faster from the KL-002 families, which it cannot build because it
has no prefix `+`/`-`, no `^`, no nested single-line IF and no PRINT
juxtaposition.

## Known limitations

- KL-002 ([validation.md](../validation/validation.md), details in
  [0.1.0-performance.md](0.1.0-performance.md#known-limitation-kl-002)), a
  class: error recovery can take time quadratic in the number of repeated
  malformed pieces that keep a right-recursive nesting pending in one
  statement or its continuation (prefix operators, `^`, nested single-line
  IFs, directives inside an expression, PRINT continued by malformed lines,
  also across lines). Through the CLI the measured families pass 10 s from
  about 5 KB (PRINT continued by malformed lines) to 29 KB (nested IFs). The
  listed families are those found; others may exist. For the measured
  families memory stays small and the runtime's progress callback stops the
  parse; the open findings B5-01 and B5-02 ([Status: hold](#status-hold)) are
  not covered by this limitation. Tree-sitter runtimes
  0.25.1–0.27.0 give the same trees and quadratic curves; valid input and
  scattered errors are not affected.
- No Level 2 (Roku device or compiler) evidence exists; V8 was not run.
  "Verified on Roku" is not claimed.
- Provisional (26), a disclosed grammar choice that Level 2 evidence may
  change: BS-LEX-003, 006, 008, 014, 024, 025, 028, 033, 035; BS-LIT-006,
  010, 017; BS-EXP-021, 027, 028; BS-STMT-008, 009, 020, 022, 026, 032, 033;
  BS-FUNC-003; BS-ERR-005; BS-COND-008, 012.
- Tolerated (10), non-normative and resting on Level 4 evidence: BS-LEX-011;
  BS-STMT-004, 011, 035, 039, 040; BS-FUNC-011; BS-ARRAY-003; BS-AA-004;
  BS-COND-015.
- Unresolved (25), not claimed either way: BS-LEX-007, 016, 020, 034;
  BS-LIT-013, 018; BS-TYPE-002; BS-EXP-022–025; BS-STMT-006, 014, 021, 028,
  034; BS-FUNC-004, 007, 012; BS-ARRAY-006, 009; BS-AA-006; BS-ERR-006;
  BS-COND-009, 010.
- Not rejected although the compiler would reject them (grammar-contract
  non-goals): reserved words used as names where they are not grammar
  keywords, literal words included (`step = 1`, `catch true`,
  `#const x = invalid`; BS-LEX-023), designators on function and constant
  names (BS-LEX-019, BS-COND-014), semantic rules (out-of-scope rows).
- Disclosed behaviour on invalid input: a word that begins with a contextual
  keyword or directive word may be split instead of rejected (`a modx`,
  `#iffy`); a label after code on the same line (`x = 1 : here:`) is
  accepted (BS-LEX-028, not contractual); inside a literal-false region a
  line whose first word is exactly `#if`, `#else` or `#end` is a directive
  (grammar-design §11); recovery
  trees are not contractual, and a missing block terminator can leave later
  declarations inside one `ERROR`.
- No language bindings, no WASM artifact, no package; consumers use `src/`.
- `go-treesitter`: V9 did not pass (recovery-tree differences in the Go
  runtime, `go-treesitter` KR-0005, on inputs with syntax errors). This
  repository makes no `go-treesitter` compatibility claim; the integration
  and its correction are separate work in that repository, on the released
  identity.
- Performance is measured on one Windows machine; the slowest measured
  families belong to KL-002; apart from them, malformed input with bare CR
  line endings (about 0.4 MB/s on the release parser, linear).
