# 0.1.0 integrated qualification

The qualification record of the re-frozen 0.1.0 candidate (Session 05-7,
2026-09-26): one candidate that closes the seven release-blocking findings of
Sessions 05-1, 05-2 and 07 on the stock Tree-sitter 0.27.0 runtime, through a
pre-release schema re-freeze
([ADR-0007](../design/decisions/ADR-0007-pre-release-schema-refreeze.md)) and
an error-recovery external scanner
([ADR-0008](../design/decisions/ADR-0008-error-recovery-scanner.md)). It
supersedes the product identity of [0.1.0-release.md](0.1.0-release.md), whose
history stays valid for the requirements, fixtures and earlier fixes.

**Status (2026-09-26): HOLD, not released.** Nothing is merged into `main`,
tagged or published. The first confirmation run of the release
qualification lane on the candidate (`lane-c1`, protocol v2) failed four
absolute-time gates; the diagnosis points to host load, not to a product
regression (below), but the registered protocol keeps the failure and
blocks Gate B until the owner decides how the lane is to be repeated.

## What changed

- **Schema re-freeze** ([tree-schema.md](../specs/tree-schema.md) "Re-freeze
  of 0.1.0"): a called member is one `call_expression` with `object`,
  `property` and `arguments`; PRINT items are direct children of
  `print_statement` without an `expression` wrapper; six error-only named
  forms (`open_parenthesis`, `open_bracket`, `minus_sign`, `plus_sign`,
  `not_operator`, `try_keyword`) appear only inside `ERROR` nodes. Every
  valid public tree projects onto the earlier schema without loss
  (SEM-PUBLIC below).
- **Error-recovery scanner** (grammar-design §16, ADR-0008 decisions 2, 3
  and 5): in the runtime's error state only, the rest of a malformed line is
  one hidden token when it is long (16 units or more), or when it is short
  and neither a statement line, a closing bracket nor the end of input
  follows; the line end of a line with a long run is a recovery line end,
  valid only where a line or a block body may begin; at the end of input an
  empty line end is returned at most twice per stack version. It produces
  no token in a valid parse.
- **Stack and node reductions**: block headers as hidden rules,
  `_block_head` and `_body`; six inlined helpers.
- **Query**: sibling-order patterns for method calls and the error-only
  forms; W11 unchanged in meaning.

- A2's 374-case context × token matrix, with a clean, short or long
  malformed line before it: no declaration lost against H; more error rows

- 4,886 single-line mutants of six samples: the candidate loses
  declarations that H keeps in 9, H loses declarations the candidate keeps in

- 2,816 generated inputs that end inside open constructs: none lost against
  H; against `e093ac8`, 206 kept and 15 lost.
- 10,000 random end-of-input files: the candidate loses declarations that H
  keeps in 105, H in 3,260; two empty end-of-input line ends against one: 19

- 9,990 byte prefixes of the samples: the root error status equals H's in

  statement follow), by H in 3,697.
- No input parses without an error where H reports one: about 60,000

## Known limitations and disclosures

- A long malformed line becomes one `ERROR` node; the tokens after the error
  point on that line are no longer separate nodes (highlight roles above).
- The recovery-shape trade-offs of ADR-0008 Consequences: a long run covers
  in-line resume points (statement after `THEN`); a stop before an unusable
  block keyword can let the next line join the malformed statement; a short
  rest before a block keyword likewise; a closing bracket ends a literal
  early; the second end-of-input line end can also enter an open construct;
  a `REM` comment after a long run on the same line is part of the run.
- Below more than 16 unclosed constructs the runtime finds no state that
  accepts the line end, and recovery may absorb lines that H keeps.
- A file cut off inside deeply nested constructs can be wrapped whole at the
  end of input (grammar stack shape; the no-op scanner gives the same trees).
- A lone `CR` stays unresolved (BS-LEX-007) and yields `ERROR`.
- RECOVERY-LOCALITY covers single-line mutants that end with a line break;
  end-of-input and multi-error behaviour is measured off-lane by the
  reviewers (B2-04), and its thresholds compare against H only.
- The lane runs on the local Windows host; hosted CI runs its CLI subset. The
  support runtimes are checked for completion within the caps only.
- Commit messages: the bodies of `86eac11` and `b501847` cite scanner hashes
  typed by hand (corrected in `e093ac8`); `494ecb2` says 32 guards (33) and
  `d3764a3` "22 with a lone CR tail" (22 with a lone `CR` and a statement);
  both corrected in the next commit bodies.
- Earlier limitations and requirement statuses are unchanged
  ([0.1.0-release.md](0.1.0-release.md#known-limitations)), except KL-002.
