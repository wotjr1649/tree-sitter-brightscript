## L4 여섯 후보의 정적 조사

BrighterScript0.73.5 commit01a359c69a05f2238b514bfca26e96517783020d의 MIT source를 읽었다.
dependencies 미설치로 동적 실행은 NOT_RUN이며 AST 수·diagnostic 수는 null이다.
plain mode 기본 firmware15.0, 명시15.3, BrighterScript mode를 구분한다. Program validation도 미실행이다.
Parser가 AST를 반환하거나 token 목록에 들어 있다는 사실을 compiler의 무진단 수용으로 간주하지 않는다.

- BS-TYPE-002: Parser.typeToken -> util.tokenToBscType -> functionParameterTypeIsInvalid / invalidFunctionReturnType. LongInteger/Invalid에는 변환 경로가 있으나 Interface는 목록에만 있고 대응 변환이 없다. BrsFile은 lexer/preprocessor/parser diagnostics를 합친다. 하위 사례: LongInteger parameter, LongInteger return, Interface parameter, Interface return, Invalid parameter, Invalid return.
- BS-EXP-023: consumeNewlinesIfAllowed는 .bs 또는 minFirmwareVersion >=15.3에만 적용. 기본15.0은 다르다. primary의 grouping은 직접 expression을 호출한다. indexedGet의 목록 양끝 newline 소비는 무조건이며 binary continuation과 별개다. 하위 사례: binary operator 다음 newline, group 시작/끝 newline, index 시작/끝 newline.
- BS-EXP-024: finishCall은 목록 처음/각 argument 시작/끝에 조건부 newline 소비를 한다. functionDeclaration/functionParameter 경로는 이 helper를 그대로 쓰지 않는다. 실제 diagnostics와 Program 결과는 미실행이다. 하위 사례: argument comma 뒤, argument 목록 양끝, parameter comma 뒤, parameter 목록 양끝.
- BS-STMT-021: TokenKind의 endfor는 EndFor다. exitfor/foreach compact 철자는 keyword가 아니며 spaced exit for/for each와 구분한다. bare exit/continue에 endfor의 결과를 전이하지 않는다. 하위 사례: endfor, exitfor, foreach, bare exit, bare continue.
- BS-FUNC-004: functionDeclaration의 isSub 분기는 AS 자체를 금지하지 않는다. Expression은 explicit return type과 implicit Void를 구분한다. BrsFileValidator의 ReturnStatement 진단은 Void/non-Void별로 다르므로 AST 존재만으로 무진단 compiler 수용이라고 할 수 없다. 하위 사례: named sub as Void, anonymous sub as Void, named/anonymous sub as other type.
- BS-COND-009: Lexer.preProcessedConditional은 # 뒤 공백을 소비하고 compact 철자를 토큰화한다. PreprocessorParser는 조건을 한 token으로 읽으며 Preprocessor.evaluateCondition은 True/False/Identifier를 구분한다. 연산식 지원으로 일반화하지 않는다. constant 이름의 lexer 규칙과 reserved-name 진단은 별개다. 하위 사례: compact #elseif/#endif, # 뒤 space/tab, 조건식, constant 첫 글자.
