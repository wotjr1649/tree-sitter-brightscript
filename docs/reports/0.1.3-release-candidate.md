# v0.1.3 source release

Status: **RELEASED_VERIFIED**. This release keeps source-only distribution and
adds hosted native validation on Windows x64, Ubuntu x64 and macOS 15 Apple
Silicon ARM64. No OS-specific compiled parser libraries, language bindings,
WASM modules or npm package are release assets.

The grammar, scanner, queries and public tree are unchanged from v0.1.2.
The generated parser changes only its version metadata from 0.1.2 to 0.1.3.
The platform work fixes macOS `ru_maxrss` units and canonicalizes the extraction
root before checking ZIP members' output paths. The original session evidence,
including the first macOS failure, is in the
[Session 08 report](session-08-cross-platform-source-validation.md).

## Independent adversarial review

A separate `gpt-6-astra/high` reviewer examined the bounded, inspected code
changes and observed gate evidence, then returned **no confirmed release
blocking finding**. This was a separate-context static review, not a direct
repository/log audit or independent native execution. The parent review also
inspected the full changed-code diff and scoped callers.

The reviewer raised two conditional risks. First, `run_posix` reads a PIPE
after `wait4`, which could stall if `parse --quiet` wrote more than PIPE
capacity. The pinned CLI says `--quiet` suppresses main output; a local
10,000-parenthesis malformed input produced 115 stdout bytes, and a valid
sample produced none. The registered CI and full lane passed; this does not
prove an output bound for every possible future input. Second, ZIP path checks
could race with another process replacing extraction directories. The actual
caller requires a new output directory under `.work`, runs in a fresh CI job
workspace, and extracts fixed, hash-checked public archives in one process.
Concurrent adversarial writes to that workspace are outside the supported
threat model. Neither concern warrants changing the reviewed code for this
release.

The reviewer also requested that generation drift and the final asset identity
be linked to the release claim. Local and three-OS `check_generated.py` passed;
the file hashes are listed above. The final asset-to-tag checks are recorded
below.
