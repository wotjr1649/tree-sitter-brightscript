## 증거의 해석

- 현재 schema는 구체 named node 60개와 supertype 2개다 (JSON의 named 항목 합계 62). Session 03의 54-node 기록은 당시 schema를 뜻한다.
- 404는 SEM-PUBLIC comparator mutant 수다. 유효 source 수가 아니다.
- 17×3은 gate 수, 8875×3은 기록된 실행 수다. 독립 source 수나 모든 환경 인증이 아니다.
- 비교 보고서의 자체 parser `2711f7cc…`는 출하 전 H다. 최종 v0.1.0 parser는
  `9d6839b3…`다. seven-blocker before 수치를 legacy grammar 수치로 읽지 않는다.
- CANCEL의 반환 시간과 CANCEL-OVERSHOOT sweep의 overshoot는 별도 집합이다.
- locality의 62/7 및 30/1은 해당 mutation 집합에서 상대가 감춘 행을 비교한 사례 수다.
  일반 오류율 감소가 아니다. 1 MiB 관측은 모든 입력 크기에 대한 보장이 아니다.
- 과거 reviewer는 별도 context의 같은 모델 계열이었다. 제3자 검토로 표시하지 않는다.
- 기존 FAIL과 정책 변경 전 결과는 [qualification 이력](0.1.0-integrated-qualification.md)에 그대로 남는다.

## Version-only 증거 (P3)

고정 CLI 0.27.0 / ABI 15로 두 clean 출력의 generated set이 byte-identical했다.
임시 source metadata만 0.1.0으로 되돌린 counterfactual 생성도 v0.1.0 tag와 일치했다.
제품 차이는 package/lock/tree-sitter version과 유일한 parser language metadata의 patch 0→1이다.
비교기의 최초 15개 대조 후 JSON boolean과 숫자를 같게 보는 도구 결함을 재현·수정했다.
별도 review가 지적한 JSON 공백·키 순서 허용도 byte 비교로 닫았다.
최종 정상 version-only 대조와 23개 변조 대조가 통과했다 (V0/V1, L3).
실제 parse-table 값, scanner token-map 값, query capture, node field 및
private/binding의 JSON type 변경을 포함한다. 변조 사본은 메모리에서만 비교하며 컴파일하지 않았다.

이는 source delta의 관측이며 모든 입력의 동등성이나 같은 latency의 증명이 아니다.

## 새 native 안전성 관측

등록 profile에서 고정 runtime의 13개 translation unit과 generated parser·scanner,
test target을 ASan/SanitizerCoverage로 계측했다. 297개 replay 행은 서로 다른
source byte hash 296개이며, 관측 cancellation은 96회다. Replay 전체 PASS.

| seed | target invocation | engine 보고 시간(초) | 관측 coverage counter |
|---|---:|---:|---:|
| 6 | 10,000 | 34 | 3,124 → 4,461 |
| 106 | 10,000 | 55 | 3,124 → 4,427 |
| 206 | 10,000 | 25 | 3,124 → 4,415 |

세 실행은 각각 `BOUNDED_COMPLETE`이고 finding을 보고하지 않았다. 실행 수는 독립
source 수가 아니다. 실제 ASan DLL 경로를 검사했으며 native 검증의 330개 supervisor
보고서는 모두 종료 확인과 active process 0을 기록했다. 가드 자기검사의 의도된 제한
종료는 제품 실행 FAIL과 구분한다.

Windows ASan의 이 입력·도구 범위만 주장한다. Leak freedom, UBSan/TSan, 모든 입력의
안전, 모든 크기의 입력, 계측 성능의 제품 latency 대체를 주장하지 않는다.
Native query는 predicate 없는 capture 완전성을 검사하며 최종 역할은 별도 CLI V4가 검증한다.

## 성능 증거 승계와 출하 경계

S572 q1/q2/q3의 각 8,875개 실행 기록을 실제 child 출력과 대조하고, 모든 측정 기반
판정을 다시 계산해 원판정과 일치함을 확인했다. 각 round의 17개 원래 gate PASS는
역사적 관측이다. 기존 FAIL·tag·asset·봉인은 보존했다.

`gates.py`, `cases.py`, probe, 입력·runtime manifests, production compiler/flags는
유지했다. `run.py`의 기존 19개 함수 AST는 같고 default supervisor binary도 S572와 같다.
새 안전성 dispatch와 test-only profile, 문서·정책·version 변경을 별도로 열거했다.
Known-bad guard의 11개 역사 FAIL raw와 변경 없는 guard/CLI 의존성도 확인했다.

P06-MAINT의 성능 row는 `execution_status=NOT_RUN`, `evidence_mode=CARRIED_FORWARD`다.
최종 dependency review와 source-only 검증까지 충족해야 승계 적격성이 닫힌다.
이 재계산은 새 native 성능 측정이 아니다.

작성자의 source·증거 재검토에 더해 sol/xhigh와 luna/max가 각각 별도 context에서
소스·필터된 근거를 정적으로 검토했다. 사람에 의한 제3자 검토나 원시 native 실행의
독립 재현은 아니다. JSON byte 비교, 계측 unit 수, 출하 guard의 ref·CI·draft·공개 ZIP
결속 및 source-only 범위 표기 지적을 수정했다. 실제 finding별 재검토 처분과 최종 C의 CI,
결정적 source ZIP·verification package·Gate B는 외부 evidence에 남긴다.
Source-only smoke는 Git 밖 source 사본에서 고정 도구로 generator/regeneration·schema·
corpus/highlight·incremental/repair·malformed scanner witness의 종료를 검사한다.
strict metadata 비교와 두 clean/counterfactual 생성은 별도 증거이며, 임의 host의 무설치 재현을 뜻하지 않는다.
새 Gate B 이전에는 main/tag/Release를 변경하지 않는다. [동결 정책](../maintenance.md)은
공개 다운로드·build 검증 완료 후 활성화한다.
