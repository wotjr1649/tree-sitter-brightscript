## 증거의 해석

- 현재 schema는 구체 named node 60개와 supertype 2개다 (JSON의 named 항목 합계 62). Session 03의 54-node 기록은 당시 schema를 뜻한다.
- 404는 SEM-PUBLIC comparator mutant 수다. 유효 source 수가 아니다.
- 17×3은 gate 수, 8875×3은 기록된 실행 수다. 독립 source 수나 모든 환경 인증이 아니다.
- 비교 보고서의 자체 parser `2711f7cc…`는 출하 전 H다. 최종 v0.1.0 parser는
  `9d6839b3…`다. seven-blocker before 수치를 legacy grammar 수치로 읽지 않는다.
- CANCEL의 반환 시간과 CANCEL-OVERSHOOT sweep의 overshoot는 별도 집합이다.
- locality의 62/7 및 30/1은 해당 mutation 집합에서 상대가 감춘 행을 비교한 사례 수다.
  일반 오류율 감소가 아니다. 1 MiB 관측은 모든 입력 크기에 대한 보장이 아니다.
- 과거 reviewer는 별도 context의 같은 모델 계열이었다. 제3자 검토로 표시하지 않는다.
- 기존 FAIL과 정책 변경 전 결과는 [qualification 이력](0.1.0-integrated-qualification.md)에 그대로 남는다.

## Version-only 증거 (P3)

고정 CLI 0.27.0 / ABI 15로 두 clean 출력의 generated set이 byte-identical했다.
임시 source metadata만 0.1.0으로 되돌린 counterfactual 생성도 v0.1.0 tag와 일치했다.
제품 차이는 package/lock/tree-sitter version과 유일한 parser language metadata의 patch 0→1이다.
비교기의 정상 version-only 대조 및 15개 변조 대조가 통과했다 (V0/V1, L3).

- 새 parser SHA-256: `e0c15ccd0148cb8a276054f9dd006f4a7afdd20e434a2dc961c057ad793b557a`.
- K1: `ebe8c4ce2c5bbe21a1b1e90d1c6a8b9824aca4931074015b6de20ccb35a19f2e`.
- K0: `cfe6a1bcad3c8fd3d7bf1d42bacedac7c1fbca770990eb659a91eabb8342ad35`.
- 알고리즘과 순서는 `scripts/check_maintenance.py`의 COMPONENTS 및 newline으로 끝나는 digest/path 목록이다.

이는 source delta의 관측이며 모든 입력의 동등성이나 같은 latency의 증명이 아니다.

## 검증 도구와 한계

historical `pilot572.py`는 return/deletion 초과와 growth 미관측이 함께 있을 때
INPUT_INELIGIBLE로 오분류함을 합성 기록으로 재현했다. 이 patch는 admission pilot을
다시 쓰지 않으므로 `OBSOLETE_NOT_USED`로 처분했다. 원본 source/raw/판정은 수정하지 않는다.
대체 경로는 새 candidate 회귀와 `check_maintenance.py`의 엄격한 동일성/의존성 증명이다.

별도 Windows test-only supervisor의 확장 profile은 정상/거부/timeout/memory/output/
자식 종료/private environment 검사와 ASan 정상/OOB, coverage 증가 control을 통과했다.
stock supervisor는 S572 바이너리와 byte-identical하다. MinGW combined fuzzer 옵션의
최초 compile 실패는 보존했으며 supported SanitizerCoverage와 같은 패키지의 engine archive를
연결한 경로를 control로 검증했다. 이는 제품 안전성 실행을 대신하지 않는다.
